# d20 条件容量研究报告：Engram、MoE 与隐状态寻址

**88 次训练、18 轮实验的结论汇总。**

本报告按结论组织。按时间顺序的原始研究日志（含每一次撤回的完整记录）见
[`conditional_capacity_study.md`](conditional_capacity_study.md)；两者数字一致，
本文重排了叙述顺序，并把"哪些想法被排除"按**想法的类别**而不是按轮次归类。

---

## 0. 一句话结论

**主线分三个阶段**（详见 §3）：**先用一次大横评选出结构，再在冠军上叠机制，
最后把大横评里被判为"竞争对手"的机制和冠军装进同一个模型。**

```
阶段一 · 大横评（5 个等参臂）        阶段二 · 叠机制        阶段三 · 组合
  dense           0.772614  ─┐
  engram（每层）    0.767606   │ 条件容量   engram_shared 0.763884
  moe             0.766529   │ −0.005      + 计数门      0.763136   combo_iso
  mobius          0.764727   │ ~ −0.009    + 解耦        0.762987   0.760625
  engram_shared   0.763884  ─┘ ← 冠军               −0.00090      −0.00236
                                −0.00873 (73%)        (7%)          (20%)
```

**总收益 0.01199**（dense → `combo_iso`，两者总参数在 0.03% 以内）。

- **73% 在第一步就拿到了。**
- 之后 11 轮、约 50 次训练在"哈希寻址 + 可学习行内容"这个空间里翻找，只贡献 **7%**，
  而且要 5 个 seed 才能把它从噪声里分出来。
- **第三步只用一次实验就贡献了 20%，是第二步的 2.6 倍。** 它没有发明任何新机制 ——
  只是把哈希记忆和路由专家放进同一个模型，总参数不变（§3.4）。

这个对比本身是本报告最有价值的方法论结论：**当一个机制家族已经连续返回十个无效结果
时，"再试第十一个"的期望收益低于"把它和另一个已知有效的东西组合"。** 这个基线率在
第 10 轮就看得出来，却又过了 6 轮才去做。

大横评本身还给出两个数字：

| | 值 |
|---|---|
| 四个条件容量臂到 dense 的距离 | 0.005 – 0.009 |
| 四个机制**彼此之间**的最大离散度 | 0.0037 |

**有这个容量，比用什么机制提供它更重要**（前者是后者的 2.3 倍）。而冠军
`engram_shared` 的 0.00873 里，一半是"装一个 n-gram 记忆"（0.00501），
一半是"让它跨层共享"（0.00372）—— 两个量级相当的结构决定，后者在原论文里
根本不是一个选项。

**但"机制差距小"这句话在第 16 轮被重新解读了。** 大横评把四个机制放在同一张排名表
上比较，隐含地把它们当成同一件事的四种做法；第三阶段证明至少其中两种是**互补**的
（§3.4）。四个机制彼此接近，不代表它们提供的是同一种东西 —— 只代表在只装一个的时候
效果相近。

主线上的三个决定各有专门的实验支撑（§4）：
1. **为什么用 token 寻址** —— 13 种隐状态寻址机制全部落在一个包含 dense 的
   0.0042 区间内（0.0040，20 倍）；
2. **为什么共享表** —— 一个完全等参的 2×2 把效应定位到**表池化**（−0.0035），
   而不是寻址一致性（小 15 倍）也不是容量；
3. **为什么门必须解耦** —— 解耦几乎不改均值，但把方差降 1.53 倍，
   这才让 1.57 倍的非结果变成 3.03 倍的已证实结果。

除主线之外，本研究在这个设计空间里尝试过的 **十三个新机制全部无效或更差**（§5）。
这个 0/13 的成功率本身是报告最重要的信息之一：在"哈希寻址 + 可学习行内容"这个空间
里，可动的旋钮基本已经动完了 —— 剩余空间约 0.001。**而离开这个空间的第一次尝试
（§3.4 的组合）就拿到了 0.00236。**

**但组合本身也很快见底了。** 第 17 轮试了把组合继续推进的两条显然路径，**两条都是
负结果**（§3.5）：Mobius 真正的那个部件（每层私有常开专家，此前 16 轮从未装过）是
0.65 倍，而去掉计数门要付 0.00127 —— 后者说明门在组合里"原样存活"，而不是"贡献更多"。
第 18 轮把最后这个便宜问题走了一遍（§3.6）：**结果不对称** —— 表偏重（73/27）可分辨地
更差（2.71 倍），专家偏重（26/74）持平到略好（1.23 倍，未解决）；内部区间单调，最优点
比 combo_iso 随手试的 44/56 更偏专家，但删掉表本身是最差臂。所以组合是一个真实的点、
不是一片新大陆；预算划分这个旋钮现在也关掉了：偏专家、留少数表。

## 1. 实验设置

所有臂完全一致，只改一个变量：

| 项 | 值 |
|---|---|
| 模型 | d20：`model_dim` 1280，20 层，10 头，`head_dim` 128 |
| 序列 / 注意力 | `seq_len` 2048，窗口模式 SSSL，mHC 4 流 |
| 批量 / 步数 | 524,288 token × 3814 步 ≈ **2.0B token** |
| 硬件 / 数据 | 4× GB200，ClimbMix |
| 指标 | 最小验证 bpb，每 500 步在 10.5M token 上评测 |
| 对齐口径 | **激活参数对齐**（918.3M），多数臂同时对齐总参数 |

`--target-param-data-ratio=-1`，即固定预算而非计算最优。

### 1.1 两个必须先说的局限

- **2.0B token 远未收敛。** d20 的计算最优约 9.5B（约 13 小时/臂）。所有臂在截断
  时仍在下降。本报告是**训练中途的切片**，排序有可能随预算改变。
- **完全没有 CORE 下游评测。** 全部 18 个运行脚本都设了
  `--core-metric-every=-1`，所以约 73 次运行**只有 bpb，没有任何下游任务结果**。
  本文的效应量多在 0.001 量级（相对 0.13%），这些差异是否能在下游任务上体现，
  **本研究无法回答**。61 个 checkpoint 尚存，可事后补测（仅推理开销），但 §1 的
  `dense` / `moe` / `mobius` checkpoint 已随 `/tmp` 清理丢失。

## 2. 方法论：误差棒是本研究最重要的产出

这一节放在结果之前，因为它决定了后面每个数字该怎么读。**本研究共发生 15 次撤回
或修正，几乎全部源于同一个错误：把小于该臂自身误差棒的差异当成了结果。**

### 2.1 不存在统一的误差棒，逐臂相差 45 倍

全部通过更换 `--engram-seed` 实测（该 seed 会置换哈希乘数，对隐状态寻址的臂还会
重抽 LSH 投影）：

| 臂 | n | sd | 类别 |
|---|---|---|---|
| `share_hash` | 2 | **3.7e-5** | 每层表 + 共享哈希 |
| *同配置重跑*（仅 CUDA 非确定性） | 2 | 4.3e-5 | **下限** |
| `shared_rank1` | 2 | 2.7e-5 | 共享 + rank-1 |
| `share_tbl` | 2 | 7.9e-5 | 共享表 + 每层哈希 |
| `engram`（每层，基线） | 3 | **8.1e-5** | 全研究最紧 |
| `split_tbl` | 3 | 1.4e-4 | 组合 73/27（表偏重；router 未重抽，**下界**） |
| `heads16` | 2 | 1.5e-4 | |
| `split_exp` | 3 | 2.4e-4 | 组合 26/74（专家偏重；router 未重抽，**下界**） |
| `lsh` | 2 | 2.7e-4 | 隐状态寻址 |
| `engram_shared` | 3 | 3.5e-4 | token，共享 |
| **`cg_dec`** | **5** | **4.9e-4** | **唯一被验证稳定的误差棒** |
| `combo_full` | 2 | 5.1e-4 | Engram+MoE（router 未重抽，**下界**） |
| `cg_fourier` | 2 | 5.9e-4 | |
| `hybrid_frac75` | 2 | 6.3e-4 | token/隐状态混合 |
| `tokens_rank1` | 2 | 7.3e-4 | token + rank-1 |
| `count_gate` | 3 | 7.5e-4 | |
| `combo_iso` | 3 | 7.9e-4 | Engram+MoE（router 未重抽，**下界**） |
| `combo_nogate` | 3 | 7.0e-4 | 组合，无门（router 未重抽，**下界**） |
| `combo_mobius` | 3 | **1.04e-3** | 组合 + 常开专家（读取路径变宽 → 方差变大） |
| `cg_dec_perlayer` | 3 | 8.7e-4 | |
| `lsh_rank1` | 2 | 1.2e-3 | 隐状态 + rank-1 |
| `cg_perlayer`（普通门） | 3 | **1.2e-3** | |

**两条实测规律：**

- **凡是加在读取路径上的机制都会放大 seed 方差。** rank-1 值在两种寻址上都约 5 倍；
  计数门在共享表上 2.2 倍、在每层表上 **15 倍**。所以新机制必须对照**它自己**被放大
  后的误差棒，而不是基线的。
- **唯一的反例是参数化方式。** 把计数门那个混合输入拆成两个线性项
  （`--engram-count-gate-decouple`）把 sd 从 7.5e-4 降到 4.9e-4，而均值几乎不动 ——
  这正是把一个 1.57 倍的非结果变成 3.03 倍的已证实结果的原因。方差不只取决于
  "加了多少机械"，也取决于**机械怎么参数化**。

### 2.2 n=2 完全不足以确定误差棒

四次实测，三次显著偏小、一次偏大：

| 臂 | n=2 的 sd | n=3 的 sd | 变化 |
|---|---|---|---|
| `engram_shared` | 1.31e-4 | 3.45e-4 | **2.6 倍偏小** |
| `count_gate` | 8.56e-5 | 7.50e-4 | **8.8 倍偏小** |
| `engram`（每层基线） | 6.36e-6 | 8.12e-5 | **12.8 倍偏小** |
| `cg_perlayer` | 1.71e-3 | 1.21e-3 | 1.4 倍偏大 |

所以这**不是单侧偏差**，而是"2 个点的极差几乎不携带 sd 信息"。

**最危险的情况是 n=2 出奇地紧。** `count_gate` 两个 seed 只差 1.21e-4，读起来像一个
异常稳定的臂，于是我据此宣布了"新最优、3.7 倍、完全分离"；第三个 seed 把 sd 变成
7.5e-4，结论退回 1.57 倍、两组重叠。**这是本研究最贵的一次教训。**

唯一被验证稳定的误差棒是 `cg_dec`：n=3 → n=5 时 sd 只涨 **1.20 倍**（其余全部涨
2.6–12.8 倍）。

### 2.3 MoE 系的臂根本无法有误差棒

`base_train` 里既没有 `--moe-seed`，也没有全局 `manual_seed`，所以重跑
`moe`/`mobius` 只采样 CUDA 非确定性（4.3e-5），不是结构上不同的抽样。**本报告中每
一个 MoE-vs-Engram 比较都是单边的**：Engram 一侧有实测误差棒，MoE 一侧没有。给
router 初始化加一个 seed 旋钮是尚未完成的工作。

### 2.4 怎么读本报告的数字

- 多数臂是 n=1。**任何小于其相关误差棒 2 倍的差距一律视为未解决。**
- 用**该臂所属类别**的误差棒，不要用全局的。用错类别的误差棒是全部 15 次撤回的
  直接原因，其中一次把 1.1 倍的结果说成了 8.7 倍。
- 优先引用 sd，不要引用极差；n≥3 之前不要引用误差棒。

## 3. 主线：大横评选结构 → 在冠军上叠机制

主线分两个阶段：**先用一次大横评在 5 个等参臂里选出结构，再在冠军上叠机制。**

**阶段一 · 大横评** —— `runs/run_d20_iso_sweep.sh`，激活参数全部对齐（918.3M），
四个非 dense 臂总参数也对齐（1820.0M，误差 +0.46%）：

| 臂 | n | min bpb | vs dense | 占主线总收益 |
|---|---|---|---|---|
| dense | 1 | 0.772614 | — | — |
| engram（每层表） | 3 | 0.767606 | −0.00501 | 57.4% |
| moe（每层私有专家池） | 1 | 0.766529 | −0.00609 | 69.7% |
| mobius（640 专家单池跨层共享） | 1 | 0.764727 | −0.00789 | 90.3% |
| **engram_shared**（记忆表跨层共享） | 3 | **0.763884** | **−0.00873** | **100%** |

**阶段二 · 在冠军上叠机制：**

| 主线 | n | min bpb | 本步 | 占总收益 | 累计 |
|---|---|---|---|---|---|
| engram_shared（大横评冠军） | 3 | 0.763884 | — | — | −0.00873 |
| + 计数门 `count_gate` | 3 | 0.763136 | −0.000747 | 7.8% | −0.009478 |
| + 解耦 **`cg_dec`** | 5 | **0.762987** | −0.000149 | 1.5% | **−0.009627** |

**主线总收益 0.00963，91% 在大横评那一步就已经拿到了。** 之后 15 轮实验、约 68 次
训练，合计只贡献 **9.3%（0.00090）**。

这个比例是本报告最应该被记住的数字。它的含义不是"后面的工作没价值"—— 恰恰相反，
后面的工作确定了**边界在哪里**：在"哈希寻址 + 可学习行内容"这个设计空间内，结构
一旦选定就几乎把能拿的都拿完了，剩下的空间只有约 0.001，而且要动用 5 个 seed 才能
把它从噪声里分离出来。想要更多，必须离开这个设计空间（§6、§9）。

冠军那 0.00873 还可以再拆成两半，**两半量级相当**：
"装一个 n-gram 记忆"值 0.00501（`engram` 对 dense），"让它跨层共享一张表"再值
0.00372（`engram_shared` 对 `engram`）。"要不要记忆"和"记忆要不要共享"是同一数量级
的问题，而后者在原论文里根本不是一个选项。两者的"为什么"分别在 §4.1 和 §4.2。

### 3.1 大横评：机制之间的差距小于到 dense 的差距

完整结果，含耗时与吞吐：

| 臂 | min bpb | vs dense | 总参 | 激活 | 耗时 | tok/s |
|---|---|---|---|---|---|---|
| **engram_shared** | **0.763884** (n=3) | **−0.0087** | 1828.0M | 918.3M | 128m | 258k |
| mobius | 0.764727 | −0.0079 | 1820.0M | 909.9M | 202m | 166k |
| moe | 0.766529 | −0.0061 | 1820.0M | 902.5M | 163m | 200k |
| engram（每层） | 0.767606 (n=3) | −0.0050 | 1828.4M | 918.3M | 127m | 262k |
| dense | 0.772614 | — | 901.7M | 901.7M | 117m | 281k |

**工程上的选择是 `engram_shared`**：质量最好，速度接近 dense（128m vs 117m，+9%）。
Mobius 达到相近质量要 202m（+72%）：一个 640 专家的大 bank 让 grouped GEMM 的效率
远低于十个小 bank，所以共享省下的参数是用吞吐换的。

**横评最重要的读法是这个比例：**四个条件容量臂到 dense 的距离是 **0.005–0.009**，
而四个机制**彼此之间**的最大离散度只有 **0.0037** —— 前者是后者的 2.3 倍。四个臂用
了完全不同的机械（哈希记忆 / 每层专家池 / 跨层共享专家池），落点却挤在一起：
**有这个容量，比用什么机制提供它更重要。**

**两个机制家族各自的"共享"版本都更好**，这是横评里唯一跨机制成立的规律：
`engram_shared` − `engram` = −0.0037，`mobius` − `moe` = −0.0018。跨层共享在两种
机制上都赢，这也是后面 §4.2 专门去拆它的原因。

**注意 MoE 系的臂没有误差棒**（§2.3），所以 `moe` 与 `mobius` 的名次以及它们与
`engram_shared` 的差距都是单边的 —— Engram 一侧有实测 sd，MoE 一侧没有。

### 3.2 机制之一：计数门 —— −0.00075，但单独看未解决

Engram 把所有 n-gram order 并行读出后用**固定权重**拼接 —— 一个出现两次的 3-gram
和一个出现一万次的 3-gram 被同等信任，一个稀有行（最可能是冲突受害者）和一个干净行
也被同等信任。经典 n-gram 语言模型里最大的单项收益恰恰是**按计数可靠性做退避/插值**
（Kneser-Ney），而 Engram 没有这个。

`--engram-count-gate` 为每个头学一个 `w = 2·sigmoid(a·log1p(命中率) + b)`，`a=b=0`
初始化因此起点严格中性。代价是 **32 个标量**，行数、总参、激活参数、FLOPs、吞吐
全部不变 —— 全研究唯一一个在每个口径上都严格等参的臂。

**结果：−0.00075，1.57 倍，未解决。** 而且它把 seed 方差从 3.45e-4 放大到 7.50e-4
（每层基座上更是放大到 1.21e-3，15 倍）。这个臂一度被我宣布为"新最优、3.7 倍、
完全分离"，第三个 seed 就把它打回来了（§2.2）。

**但它学到的东西可靠得多。** 6 个独立门、96 个头**全部为负**：命中越多越不被信任 ——
从零学出的 Kneser-Ney 退避，有效逆频率指数约 **−0.3**，且更稀疏的高阶头被压得更狠、
更深的层退避得更狠。**这里有一个分离：模型可靠地学会了退避，而退避并不可靠地改善
bpb。** 两半都是结论。

### 3.3 机制之二：解耦 —— 均值几乎不动，但让它变得可测量

计数门的输入只有一个"行命中率"，而它混淆了两件相反的事：**这个 n-gram 本身频繁**
（好，内容可靠）与**这一行很拥挤**（坏，内容是糊的）。
`--engram-count-gate-decouple` 把它拆开：

```
f_o = 该 order 内所有头的最小命中率  →  这个 n-gram 自身的频率
c_h = rate_h − f_o                   →  该头的冲突超出量（≥0）
rate_h = f_o + c_h                    严格相等，是分解而非近似
```

**这个分解是免费的**：同一 order 的每个头用**不同的质数**哈希**同一个** n-gram，
所以"频率造成的热"在该 order 的所有头上共同出现，而"冲突造成的热"在头之间独立。
不需要基数估计（HyperLogLog 之类），不需要新 buffer —— 所有 H 个命中率本来就已经
按位置取出来了，只需一次 8 头的 min 归约。额外 64 个标量。

| 基座 | 臂 | n | 均值 | sd | vs 基线 |
|---|---|---|---|---|---|
| 共享表 | `count_gate` | 3 | 0.763136 | 7.50e-4 | −0.00075，1.57 倍（未解决） |
| 共享表 | **`cg_dec`** | **5** | **0.762987** | **4.89e-4** | **−0.00090，3.03 倍** |
| 每层表 | `cg_perlayer` | 3 | 0.766809 | 1.21e-3 | −0.00080，1.14 倍（未解决） |
| 每层表 | **`cg_dec_perlayer`** | 3 | 0.765924 | 8.72e-4 | **−0.00168，3.33 倍** |
| | **合并（6 vs 6 组）** | | | | **−0.00110，4.29 倍** |

**关键在于：均值几乎没动（`cg_dec` vs `count_gate` = 0.63 倍，无法区分），
是方差降了 1.53 倍**，这才把一个 1.57 倍的非结果变成 3.03 倍的已证实结果。
它也是本研究**唯一在两个独立基座上都成立的机制**，两个估计统计上一致（相差 1.34 倍）。

而且它是**唯一一个误差棒被验证稳定的臂**：n=3 → n=5 时 sd 只涨 1.20 倍，其余全部涨
2.6–12.8 倍。为什么必须解耦、以及这个"靠方差取胜"的路径为什么按基座不同，见 §4.3。

### 3.4 阶段三：把两个机制装进同一个模型 —— 第一个组合结果

**十五轮里从来没有把它们放在一起。** 大横评把哈希记忆和路由专家当成竞争的四个候选，
之后 11 轮全部在哈希记忆内部翻找。到第 15 轮为止，这个空间里的十一个机制想法只有
一个成立 —— 第十二个的先验很差。所以第 16 轮改为**组合两个已知有效的东西**。

两个臂都是 `cg_dec` 配方（共享表 + 解耦计数门）**加上**一个 Mobius 式跨层共享专家池
（`--moe-share-blocks=1`、`--moe-every=2`、N 选 8、`d_ff_expert=640`），dbs=8。

| 臂 | engram slot | 专家数 | 总参 | 激活 | FLOPs/token | n | 均值 | sd | tok/s |
|---|---|---|---|---|---|---|---|---|---|
| `cg_dec`（参照） | 30 | — | 1828.0M | 918.34M | 3.135e9 | 5 | 0.762987 | 4.89e-4 | ~257k |
| **`combo_iso`** | 15 | 357 | **1827.5M** | 922.91M | 3.162e9 | 3 | **0.760625** | 7.92e-4 | 170.8k |
| *`combo_full`* | 30 | 640 | *2746.3M* | 926.53M | 3.184e9 | 2 | *0.757196* | 5.06e-4 | 155.8k |

各 seed：`combo_iso` 0.760619 / 0.759836 / 0.761419；`combo_full` 0.756838 / 0.757553。

**`combo_iso` 是有纪律的那个臂** —— 总参数与 `cg_dec` 相差 **0.03%**，只是把同一份预算
按 44/56 分给"表"和"专家"，而不是全押在表上。

| 比较 | 差值 | Welch SE | 倍数 |
|---|---|---|---|
| `cg_dec` − `combo_iso` | **−0.002363** | 5.07e-4 | **4.66 倍** |
| `combo_iso` − `combo_full` | −0.003429 | 5.80e-4 | 5.91 倍 |
| `cg_dec` − `combo_full` | −0.005792 | 4.19e-4 | 13.82 倍 |

**而且是完全分离**：`combo_iso` **最差**的 seed（0.761419）比 `cg_dec` 五个 seed 里
**最好**的（0.762400）还好 9.81e-4。三个 seed 全部落在 0.7598–0.7614，远低于预登记的
0.7630 门槛。

**预登记成立的是"互补"这一支。** 在固定参数预算下，混着放比全押记忆好。−0.00236 是
本研究**第二大的等参机制效应**，仅次于表池化的 −0.0035，大于解耦计数门的 −0.00110。

这支持 §6 的机制解释，而不是"容量就是容量"的读法：**token n-gram 地址携带的是残差流
已经丢掉的外部信息（准确的表面形式），而 MoE 专家是隐状态的一个可学习的输入相关
函数。** 信息不同、机器不同，所以相加。如果两者只是同一种条件容量的两种买法，混合应该
落在 0.7630 附近 —— 它没有。

**三个必须同时读的限制（都在实验前写好）。**

1. **组合臂多带 +0.50% 激活参数、+0.87% FLOPs**，全部来自 MoE 路由器（1280 × 专家数，
   10 层读）。不动 `moe_every` 就无法去掉，所以按预登记：组合**赢**是部分被混淆的，
   只有组合**输**才是决定性的。反驳这个混淆的界：路由器约 4.6M 参数，而把整张共享表
   翻倍（+910M）只买到 −0.00056（§5.2）。要用 4.6M 做出 −0.00236，需要约 500 倍于
   表行的单参数效率。这是提示，不是证明。
2. **误差棒是下界。** `--engram-seed` 只置换哈希乘数，**不重置 MoE 路由器** ——
   `base_train` 里没有 `--moe-seed` 也没有全局 `manual_seed`（§2.3）。所以三个 seed
   共享同一个路由器抽样，4.66 倍偏乐观。**完全分离**那半个结论更稳。
3. **`combo_full` 不等参**（+50% 总参），按预登记必须读作"参数多了也有帮助"的一部分。
   它确立的是这个组合**还没有饱和**：`dense − combo_full` = 0.01578，是大横评冠军
   0.00873 的 **1.81 倍**。它的 +918.8M 买到 −0.00343，单参数效率约为表翻倍斜率的 6 倍
   —— 但它同时放大了表（455→909M）**和**专家（585→1049M），所以这不是单轴的容量测量，
   不应再往下推。

**代价：这是本研究第一个不免费的结果。** `combo_iso` 只跑到 170.8k tok/s，对 `cg_dec`
的 ~257k 是**慢 1.51 倍**（194 分钟 vs ~128）；`combo_full` 155.8k，慢 1.65 倍。之前所有
机制都是在吞吐几乎不变的情况下改动 bpb 的。

**路由器健康：没有塌缩。** `loss_free` 均衡器不带 aux 项（全程 `aux_loss: 0.00000`，
符合设计），均衡完全靠 bias。

| 臂 | 负载熵 起→末 | 上限 `ln(专家数)` | regret 起→峰→末 | `max_vio` 起→末 |
|---|---|---|---|---|
| `combo_iso` | 5.794 → 5.502 | 5.878 | 0.054 → 0.090 → 0.032 | 1.94 → 8.20 |
| `combo_full` | 6.296 → 5.981 | 6.462 | 0.076 → 0.146 → 0.044 | 2.88 → 9.60 |

负载熵最终为均匀上限的 **93.6%** 和 **92.5%**，regret 结束时比开始时更低，所以路由器
没有退化，Engram 的存在没有把它饿死。但 `max_vio` 是**上升**的（约 2 → 8–10，即最重的
专家最终承担约 9–11 倍于均匀的负载），这是真实的不均衡。

**一个无法从现存产物修复的限制：** §1 大横评里不带 Engram 的 `mobius` 日志已被 `/tmp`
清理销毁（§8），所以**没有基线路由器轨迹可比**。`max_vio ≈ 9` 是这个配置的常态、还是
Engram 引起的退化，**未知**。本轮原本想问的"机制交互"问题因此无法回答，只能报告绝对
健康度。为不带 Engram 的对照保留路由器统计，现在是问这个问题的前置条件（§9）。

### 3.5 第 17 轮：组合方向的两个显然后续都是负结果

两个臂都与 `combo_iso` **完全等参**（总参 0.000%、激活 ≤0.008%、FLOPs ≤0.020%，
在 meta 上和各自运行的自身打印里都验证过：1827.5M / 922.8M 对 922.91M）。

| 臂 | 配置 | n | 均值 | sd | 极差 | vs `combo_iso` |
|---|---|---|---|---|---|---|
| `combo_iso`（参照） | 357 专家，top-8，cg_dec | 3 | 0.760625 | 7.92e-4 | .759836–.761419 | — |
| `combo_mobius` | 347 专家，top-**7**，+ 每层私有常开 640 专家 | 3 | 0.761117 | **1.04e-3** | .759994–.762051 | +0.000493，**0.65 倍** |
| `combo_nogate` | 357 专家，top-8，**去掉计数门** | 3 | 0.761898 | 7.05e-4 | .761113–.762476 | +0.001273，**2.08 倍** |

#### `combo_mobius`：Mobius 真正的那个部件没有用 —— 而它从来没被跑过

**本研究把一个臂叫了 16 轮"mobius"，却一直没装它的定义性部件。** §1 的 `mobius`
和第 16 轮的组合都只用了 `--moe-share-blocks=1`，两者都没传 `--moe-shared-d-ff`，
也就是都没有 Intern-S2-Mobius 在共享池之上加的那个**每层私有的门控稠密专家** ——
正是这个部件让"共享池"不只是权重绑定。本臂把它加上，并且代价精确对齐：一个常开的
640 宽专家正好等于一个路由专家，所以 top_k 8→7 加 n_experts 357→347 恰好抵掉。

**结果：+0.000493，0.65 倍 —— 未解决，而且方向偏差。** 预登记的**"可互换"**那一支
成立：在固定预算下，条件容量**放在哪里**不重要，只有**有多少**才重要。这条
**把 `--moe-shared-d-ff` 作为旋钮判死**，同时说明 §1 的遗漏是无害的 —— 那个臂定义
不完整，但不影响它的数字。

**模型确实在用这个东西，只是用了也没收益。** 共享专家的门是零初始化的
（`sigmoid(x·g)` 在第 0 步对任何输入都等于 0.5）。训练后它跑得很远：逐层 ‖g‖，三个
seed 在 7–33 之间（初始为 0），均值约 0（±0.04），也就是会摆到 0.5 两侧，在这个模长
下接近硬开关。**但哪些层拿到大门在 seed 之间不一致**（第 4 层 8.2 / 30.3；第 10 层
31.7 / 16.1 / 20.8），所以没有可报告的深度规律。自洽的解读是：**一个带门的常开专家
在功能上就是又一个路由器，而路由池已经在做这件事了。**

它还把 seed 方差抬到 **1.04e-3**，是所有组合臂里最宽的 —— 符合"凡是加在读取路径上的
机制都会放大方差"（§2.1），也提醒我们：真正"免费"的臂是那些什么都不改的臂。

#### `combo_nogate`：计数门在组合里依然有效

去掉 `--engram-count-gate{,-decouple}` 要付 **+0.001273，2.08 倍** —— 臂变差了，
所以在 MoE 存在的情况下这个门仍然在干活。

**但要小心读它的量级，不要宣称强版本。** 门在组合里值 −0.00127 ± 6.1e-4，单独时值
−0.00090。两者相差 0.00037，远小于任一误差棒。所以诚实的表述是：**门的贡献在组合中
存活，量级与它单独时在统计上无法区分。** 预登记里"在 MoE 存在时贡献**更多**"那一支
**没有**被证实 —— 我把 >0.7619 那一档标成了那个含义，而均值落在 0.761898，刚好在其
下方，倍数也只是勉强过 2。**那一档标错了**：在这个功效下，"原样存活"和"贡献更多"
不可分离，只有前者站得住。

不过它确实回答了这个臂被造出来要问的问题。第 16 轮的 −0.00236 是拿"cg_dec + MoE"
对"cg_dec"测的，门自己那一半从未在组合内部复核过。**它没有被 MoE 吸收。**
§9 里"cg_dec 换第三个基座"这一项因此部分完成：组合就是第三个基座，而门迁移过去了。

**学到的系数第四次复现，而且拥挤对应关系变得更锐利。** 三个 seed，从 checkpoint 读出：

| seed | `count_gate_scale` | `freq_scale` | `collide_scale` |
|---|---|---|---|
| s0 | −0.563 | **+0.305** | **−0.140** |
| s1 | −0.550 | **+0.287** | **−0.159** |
| s2 | −0.571 | **+0.314** | **−0.163** |

符号与 §4.3 一致 —— 频率好、冲突坏 —— 现在是第四个基座。而 `collide_scale` 在这里是
**−0.14 到 −0.16，而普通共享表上是 −0.087**。这些组合臂用 `slot_multiplier=15`，
也就是 `cg_dec` 的 slot 30 的**一半行数**，所以更拥挤，门也就相应罚得更狠。这是
§4.3 那个拥挤对应关系的**第三次定量确认，且方向与预测一致**。

#### 路由器：一个干净的确认，一个被推翻的预测

| 臂 | 负载熵 起→末 | 上限 | regret 起→末 | `max_vio` 起→末 |
|---|---|---|---|---|
| `combo_iso` | 5.7939 → 5.4920 | 5.878 | 0.05422 → 0.02792 | 1.9427 → **7.9702** |
| `combo_nogate` | 5.7939 → 5.4527 | 5.878 | 0.05422 → 0.03507 | 1.9427 → **9.1237** |
| `combo_mobius` | 5.7516 → 5.4614 | 5.849 | 0.04792 → 0.02947 | 2.1981 → **9.2619** |

**预登记的 `max_vio` 预测失败了。** 我预测如果私有常开专家吸走负载，
`combo_mobius` 的 `max_vio` 应该比 `combo_iso` **改善**。实际**更差**（9.26 对 7.97）。
加常开容量并没有给路由器减压；两边负载熵都还是上限的 93.4%。

**以及一个对"router 未重抽"这条警告的干净确认。** `combo_nogate_s0` 第一条 MoE 日志
与 `combo_iso_s0` 的**逐字节相同**（regret 0.05422、max_vio 1.9427、熵 5.7939），
而这是不同的 Engram 配置、不同的运行。这直接证明 `--engram-seed` 不碰路由器，
组合家族里**每一个误差棒都是下界**（§2.3）。这也意味着这两个臂之间 7.97 → 9.12 的
分化只能归因于 Engram 的计数门：去掉它，路由器**更不均衡**。这是一个值得记一行的
机制交互，但是 n=1，不值得为它单开一个臂。

#### 这一轮让组合这条线损失了什么

第 16 轮的头条完好无损：`combo_iso` 仍然是 −0.00236、4.66 倍、seed 完全分离。
第 17 轮拿掉的是**把它继续推进的三条显然路径里的两条**。剩下那一条 —— 扫描
表/专家的预算划分，而它的两个端点都已经测过 —— 现在是组合方向上唯一一个便宜且
梯度方向已知为正的项目，因此升到 §9 的第一位。

### 3.6 第 18 轮：走一遍表/专家的预算划分 —— 最优点比 44/56 更偏专家

第 16 轮把哈希记忆和路由专家装进同一个模型，用的是**第一个试的**预算划分（44/56
表/专家），它赢了。这个划分是随手挑的，不是选出来的，所以组合里最后一个便宜问题是：
它是不是接近峰值，还是只是一个采样点。两个远端点都已测过（`cg_dec` = 100/0；
`mobius` ≈ 0/100），所以这是在一条已知有内部最优的曲线上做**插值**。两个侧翼臂，各自
与 combo_iso **总参等参**（2330.7–2330.9M，±0.005%），把记忆行数与专家数对调。dbs=8，
每臂三个 Engram seed。

**五点曲线**（表% / 专家% 的条件预算）：

| 划分 | 臂 | slot | 专家 | n | 均值 | sd | vs `combo_iso` |
|---|---|---|---|---|---|---|---|
| 100/0 | `cg_dec` | — | 0 | 5 | 0.762987 | 4.89e-4 | +0.002362 |
| **73/27** | **`split_tbl`** | 25 | 172 | 3 | **0.761884** | 1.41e-4 | **+0.001259，2.71 倍** |
| 44/56 | `combo_iso`（参照） | 15 | 357 | 3 | 0.760625 | 7.92e-4 | — |
| **26/74** | **`split_exp`** | 9 | 468 | 3 | **0.760038** | 2.42e-4 | **−0.000587，1.23 倍** |
| 0/100 | `mobius` | — | ≈∞ | 1 | 0.764727 | — | +0.004102 |

**预登记的"不对称"结果成立。** 表偏重那侧（73/27）**可分辨地更差**，2.71 倍（三个 seed
都在 0.7617 以上，sd 1.4e-4 —— 家族里最紧的误差棒）。专家偏重那侧（26/74）是
**持平到略好**，1.23 倍 —— **未解决**（一步侧翼可能只值 0.0005–0.0010，低于这个
n=3-对-n=3 配对能分辨的约 0.0010），但它是采样点里最好的一个，且它没有任何一个 seed
超过 combo_iso 最差的 seed。**读形状，不读单个间隙**：**内部区间是单调的** ——
0.762987 → 0.761884 → 0.760625 → 0.760038，随预算从表移向专家而下降 —— 只在纯专家墙
（`mobius`，无表，整个家族里最差的点）才回升。

**这说明什么，不说明什么。** 这个划分**是**一个活的旋钮，而且指向专家侧：44/56 不是峰值，
本研究本该采样更偏专家的一侧。但表并非可有可无 —— 完全删掉它是测过的最差臂。最优点位于
26/74 与纯专家极端之间，比 combo_iso 随手试的那个更偏专家。这一轮**不能**说的是：专家侧
到底比 44/56 好多少 —— −0.00059、1.23 倍低于分辨率，诚实的说法是"至少一样好"，不是"更好"。

**混淆项救不了表偏重那侧。** `router_active` 随 `n_experts` 增长，所以 split_exp 多带
+0.100% 激活、split_tbl 少 0.166%（约 3.8M 的跨度），系统性地偏袒专家臂。但按尺度算，
+910M 的**表**只买到 0.00056（§3.4 系），所以 3.8M 值约 1e-6：它连那个未解决的 0.00059
都解释不了，更别说表偏重那侧输掉的、已解决的 0.00126。梯度是真的，不是记账假象。

**`collide_scale` 证实了拥挤机制 —— 并且打到了本研究的最大值。** Engram 学到的
`collide_scale` 系数追踪表的拥挤程度：每次读到的行越少，哈希碰撞越多，模型越倚重碰撞通道
来补偿。直接从六个 checkpoint 读出（无前向），|collide_scale| 的均值随表大小在测过的每个
slot 上单调：

| slot（行/读） | 30 | 25（split_tbl） | 15（combo_iso） | 9（split_exp） |
|---|---|---|---|---|
| collide_scale 均值 | −0.087 | −0.093 | −0.15 | **−0.219** |

slot 9 是本研究跑过的最小的表，显示出**最大的 |collide_scale|**（三个 seed 间 −0.20 至
−0.23），与预登记一致。`count_gate_scale` 和 `freq_scale` 也随表变小而缩小
（−0.60→−0.50、+0.36→+0.22），符合"更小的表能被门控的干净逐-n-gram 信号更少"。

**两臂的 MoE 路由都健康、归一化后可比。** 最终均衡统计（loss_free）：

| 臂 | 专家 | regret | max_vio | 熵 | 熵 / ln(n) |
|---|---|---|---|---|---|
| `split_tbl` | 172 | 0.0262 | 5.15 | 4.79 | 93.0% |
| `split_exp` | 468 | 0.0387 | 8.83 | 5.72 | 93.1% |

两者都在**各自熵上限的 93%** —— 路由不塌缩，两侧都不是瓶颈。`max_vio` 随 `n_experts`
上升（专家越多，单个专家越有空间过载），是预期的，不代表利用率更差。这就把这个划分作为
旋钮关掉了：答案是"偏专家、留少数表"，而确切峰值低于这份算力预算能给每臂买到的分辨率。

## 4. 主线上的三个"为什么"

### 4.1 为什么是 token 寻址，而不是隐状态寻址？

Engram 原始设计哈希 token id，只能按**表面形式**索引。把地址换成该层隐状态的离散化
结果，理论上表达力更强。实测**全部失败**：

| 臂 | 地址来源 | 可学习 | min bpb | vs tokens |
|---|---|---|---|---|
| tokens | 哈希 token id（论文） | 否 | **0.767606** | — |
| lsh | 冻结随机投影 → 符号位 | 否 | 0.771535 (n=2) | +0.0039 |
| pkm | 乘积键，软 top-k 读 | 是（完全可微） | 0.771378 | +0.0038 |
| pq | 乘积量化码本 | 是（STE） | 0.772703 | +0.0051 |
| lsh_n1 | LSH，**去掉 n-gram 窗口** | 否 | 0.773514 | +0.0059 |
| *dense* | | | *0.772614* | |

**最强的证据是这个零结果，而不是正结果：13 种不同的隐状态寻址机制全部落在一个
0.0042 宽的区间里，而这个区间包含 dense。** LSH 的 3 种码宽、乘积量化、乘积键、
每头独立隐变量、EMA 位平衡、rank 0/1/4 的行内容、33k 到 360k 的行数 —— 机制之间的
离散度**小于**它们到 dense 的距离。这不是 13 次实现失败，这是信息量的天花板。

原因对原设计不太友好：**一个用量化隐状态寻址、返回可学习参数的记忆，是"关于 h 的
可学习函数"的一种更差的参数化**，比旁边那个 MLP 更差 —— 它在一个随机硬划分上是
分段常数的，而 MLP 是光滑的。MoE 正是把这个函数做对的版本（带可学习路由），它比
任何隐状态臂都好 0.0068。

补充诊断（在真实验证批上测得，逐 Engram 层）：

| 臂 | 实现码熵 | 不同码数 | 行唯一性 | 隐状态有效维（90% 方差） |
|---|---|---|---|---|
| tokens | 7.84 / 14.53 bit (54%) | 413 / 1024 | 0.862 | 157–205 / 1280 |
| lsh | 9.21–9.81 / 15 bit (61–65%) | 716–932 / 1024 | **0.994** | 232–239 / 1280 |
| pq | 2.44 / 12 bit (20%) | **38** / 1024 | 0.184 | **1** / 1280 |

- **LSH 在每个指标上都更健康，却还是输了。** 它的地址分散度（0.994）优于 token
  （0.862）—— 所以**地址容量/熵不是瓶颈**。
- **PQ 把表示塌缩了，而且是自伤。** commitment loss 把隐状态往质心拉，而它被加在一个
  活跃的残差流上，结果 Engram 层的 90% 方差集中在**一个方向**上，一个 926M 参数的表
  只有 38 个有效地址。`codebook_usage` 读到 0.97 是误导性的：质心保留了早期的 EMA
  质量，而活跃状态已经塌缩。commitment loss 降到 1e-4 是**病态**读数，不是良性的。

### 4.2 为什么是共享表，而不是每层表？

这一节是本研究最干净的一组结果。一个完全等参数的 2×2（710,580 总行数、909.5M 表
字节、918.34M 激活参数，`dbs=8`）把"共享"拆成两件事：

| | 每层哈希 | 共享哈希 |
|---|---|---|
| **每层表**（2 × 355,290 行） | `engram` **0.767606** (n=3, sd 8.1e-5) | `share_hash` **0.766863** (n=2, sd 3.7e-5) |
| **共享表**（1 × 710,580 行） | `share_tbl` **0.763604** (n=2, sd 7.9e-5) | `engram_shared` **0.763884** (n=3, sd 3.5e-4) |

```
主效应 表池化   : −0.003491
主效应 哈希共享 : −0.000232   ← 小 15 倍
交互项           : +0.001023   ← 比哈希主效应还大
```

**池化就是全部效应；共享寻址方案只值它的 7%。** 交互项是一个可解释的交叉：

- **每层表时，共享哈希有帮助**：−0.00074，**10 倍**（保守；用它自己的 n=2 sd 是 13.9 倍）。
- **共享表时，共享哈希反而有害**：+0.00028（1.35 倍，未解决）。让同一个 n-gram 在
  两个深度命中**同一行**，意味着每个 n-gram 只占一行而不是两行，所以一致寻址
  **没有充分利用**共享池。

最后这点直接推翻了"共享之所以有效，是因为一行接收所有读取层的梯度"这个说法：
**最大化"同 n-gram 同行"的那个配置，恰恰是两个共享表格子里较差的一个。**

**池化不是什么**（三次独立排除，每次一个专门的臂）：

| 假设 | 证伪方式 |
|---|---|
| 是容量 | 在**每次读取行数相同**时，共享仍然赢 0.00372（9.3 倍），而只用 67% 的存储 |
| 是寻址一致性 | 比池化小 15 倍，且在共享表上符号相反 |
| 是"匹配行的联合训练" | `share_tbl` 打破了逐 n-gram 的行对应关系，一点没损失 |

### 4.3 为什么计数门必须解耦？

学到的参数给出了答案，而且是定量的。跨两个基座、两个 seed 共 7 个门，
**每一个都是 16/16 头符号一致**：

| 运行 | 门 | 频率项 `a` | 自频率 `e` | 冲突项 `d` |
|---|---|---|---|---|
| `cg_dec_perlayer_s0` | 第 2 层 | −0.479 | +0.319 | **−0.372** |
| `cg_dec_perlayer_s0` | 第 6 层 | −0.482 | +0.109 | **−0.278** |
| `cg_dec_perlayer_s1` | 第 2 层 | −0.497 | +0.309 | **−0.345** |
| `cg_dec_perlayer_s1` | 第 6 层 | −0.464 | +0.107 | **−0.260** |
| `cg_dec_s3` | 共享 | −0.599 | +0.402 | −0.087 |

- **冲突项恒为负**：行越拥挤越不被信任 —— 分解所依赖的预测成立。
- 在 `f = c = 1` 处求导：`∂logit/∂c = −0.343` vs `∂logit/∂f = −0.101`，即
  **冲突被惩罚的陡度是真实频率的 3.4 倍**。频率是好的，拥挤是坏的，模型分得很清 ——
  而未解耦的门只能看到两者之和，无法表达这个区别。
- **冲突项在每层表上大 3–4 倍**（−0.26 ~ −0.37 vs 共享的 −0.087）。每层表每层只有
  一半的行，所以更拥挤，门就惩罚得更狠。**这是一个学到的参数与一个结构事实之间的
  定量对应**，也是分解确实在度量它所声称的东西的最强证据；它同时解释了每层基座上
  更大的均值效应 —— 那里有更多拥挤可修。

**未解释的部分：** 达成显著的路径按基座不同。共享表上靠**压低方差**，每层表上靠
**均值翻倍**（−0.00168 vs −0.00080）而方差仍高。所以"解耦是一个通用的条件数修复"
这个描述过于简单 —— 我曾据此预测每层表的 sd 会降到 ~4e-4，实测 8.72e-4，**预测失败**。

## 5. 被排除的方向（按想法类别归类）

### 5.1 行内容的表达力 —— 死路

| 想法 | 固定行数时 | 等总参时 |
|---|---|---|
| rank-k 值（行是 h 的低秩映射而非常向量） | 中性（0.02 倍、0.09 倍，两次独立测量） | 输，损失 = 行数代价 |
| k/v 分离（行自带 key 供门使用） | 中性（0.9 倍） | 输，损失 = 行数代价 |

**把行的字节花在除"更多行"之外的任何东西上，都是中性到负面的。** 两个独立特性、
四次测量、同一个结论。

其中 rank-k 这一支还有额外的负面证据：在最好的臂上**有害** +0.00257（12.8 倍），
并且把 seed 方差放大约 5 倍。最有利的一次测试是 `lsh_r1_isorow` —— 与 `lsh` 完全
相同的寻址、**1.9 倍的参数** —— 结果是 +0.00013。事前声明的证伪条件是"如果在
1.9 倍参数和相同寻址下还赢不了，这个说法就死了"，它没赢。

k/v 分离的两个臂还顺带隔离出一个副产品：`kv16`（门输入 1280→256）比 `kv80`（门输入
不变）多损失约 0.0011，即**把关联门的输入变窄要付 0.0011 的代价** —— 门需要宽的
视野，但不需要自己的 key。

### 5.2 容量与冲突 —— 三个独立的否定

**表已经饱和。** 从 checkpoint 的命中率 buffer 逐 order 读出：

| | 空行占比 | p99 命中率 | 最大 |
|---|---|---|---|
| order-2 头 | 0.1% | 8.6 | **1670×** |
| order-3 头 | 0.0% | 3.8 | 575× |

基本每一行都被占用，每个 EMA 窗口内每行约 7（order-2）到 21（order-3）次命中：
**不同 n-gram 的数量远超行数。** 这一条封死了对冲突问题的两个直觉反应：

| 手段 | 结果 |
|---|---|
| 更好的哈希函数 | **不可用** —— 表已饱和，均匀哈希在最大负载上已接近最优（只差 power-of-choices 的 log-log 因子） |
| 更多行 | 共享表 −0.000533/倍（log 线性，跨 8 倍行数），每层表**完全平坦** |
| 更多独立哈希（头数 8→16→32） | **0.13 倍**：4 倍的头数扫描总跨度 5.1e-5，而误差棒是 3.45e-4 |

头数那一项值得单独说：由于 表字节 = 头数 × 行数 × 头维，而 头维 = memory_dim/头数，
**表大小与头数无关**（8/16/32 头分别 1827.94M / 1828.02M / 1828.16M，激活参数与
FLOPs 完全相同）。这是本研究少有的严格单变量扫描，而结果是零。

**结论：冲突是被容忍的，不是被消除的。** 记忆在每行 7–21 个 n-gram、order-2 头有
1670 倍长尾的状态下运行，而它并不在意 —— 既不在意更多空间，也不在意把干扰在更多
独立抽样上平均掉。`collide_scale` 度量的东西是真实的（16/16 符号一致、行越少越大），
但它的**损害**似乎已经在一个这三个手段都推不动的地板上。

顺带修正一个我过度推广的结论：0.00195/倍 的"行容量定律"是在**一对隐状态臂**上测的
（`lsh` 360k 行 vs `lsh_r0_slot4` 131k 行），然后被拿去给 `lsh_rank1` 和 `kv80` 扣
"行数代价"—— 所谓"三次独立验证"其实是同一次测量戴了三顶帽子。在 token 臂上直接扫
行数得到的斜率是 **−0.000533/倍（共享）** 和 **约 0（每层）**。

### 5.3 门控的参数化 —— 两个否定，一个正面（已在 §3.3）

| 想法 | 结果 |
|---|---|
| 固定指数的读出白化（`readout_whiten`） | 设成**学到的** −0.3 指数：+0.00218，**5.5 倍有害**。出厂默认的 power 1.0 更糟。这是负面结果，不是"未测试"。 |
| 在计数通道上加 Fourier 基 | 两次都是单调的。给了一个可证明能拟合单峰曲线的基（测试里拟合到 5e-3，而线性门做不到 5e-2），模型学出来的还是峰值在计数 0 处的单调递减；两个 seed 的曲线相关 **0.9996**。 |
| Fourier 基 + 解耦通道 | 系数退化。Fourier 基作用在 `log1p(f)` 上会**吸收**频率通道，把它的线性系数变成噪声 —— 这一点我一度误读为"模型忽略了解耦"，普通解耦臂（§4.3）的 16/16 符号一致证明并非如此。 |

Katz 折扣的直觉（低计数因为估计不可靠而应被折扣 → 信任曲线应是单峰的）**在两次
独立测试后被否定**，第二次已经把混淆因素去掉了。**在原始命中率上做单调的逆频率
加权，就是 Engram 想要的东西。**

### 5.4 更长的 n-gram order —— 更差

`cg_n5`（order 2–5，32 头）比 order 2–3 差 +0.00156（1.8 倍）。曾被列为"下一步该做的
第一项"，理由是 order 4–5 提供 h 已丢弃的精确表面信息。理由可能对，优先级是错的。

给复现者的尺寸提示：32 头 × 40 维 @ slot 30 与 16 头 × 80 维 @ slot 30 等参；而
`max_ngram_size=4` 在 `memory_dim=1280` 下**不可能**（24 不整除 1280），5 可以（32 整除）。

## 6. 目前站得住的机制解释

把所有臂 —— 以及外部文献 —— 按**信息从哪里进入**排列：

| | 地址 | 值 | 结果 |
|---|---|---|---|
| token Engram | **外部**（token id） | 可学习 | −0.0040 vs 隐状态寻址 |
| kNN-LM / RETRO | 内部（h） | **外部**（语料续写） | 有效（已发表） |
| 隐状态 Engram | 内部（h） | 可学习 | ≈ dense，13 种机制皆然 |
| dense MLP | — | 可学习 | 基线 |

**地址和值之中，至少要有一个携带来自模型自身前向计算之外的信息。** 我们的隐状态臂
两者都没有 —— 这正是为什么没有任何量化器、码宽、行数或行秩能救它们。

注意这**不是**在说"按 h 寻址本身错了"：kNN-LM 就是按 h 寻址并且有效，因为它的**值**
是来自真实数据的经验续写分布。我们按 h 寻址、返回可学习向量，那是另一个东西。

## 7. 唯一剩下的大谜团：池化为什么有效

- `share_tbl`：每层可寻址 710,580 行，**一张** 909.5M 的表 → **0.763604**
- `perlayer_slot30`：每层可寻址同样的 710,580 行，**两张**共 1819M 的表 → **0.767602**

**每次读取的行数相同、参数少一半、结果好 0.0040，而且没有逐 n-gram 的行对应关系。**
池化情形下，一行会被第 2 层为某个 n-gram 读、被第 6 层为另一个 n-gram 读，所以它的
内容处于叠加态 —— 而这居然**优于**给每层各自一行私有的行。

容量、寻址一致性、匹配行的联合训练都已被排除（§4.2）。领先的假设是：**池化的行从
每一个读取层收集梯度，所以在固定 token 预算下每参数被训练得更好。** 这个假设有一个
可证伪的预测：**池化的收益应随训练变长而缩小。** 2.0B token（约为计算最优的 21%）
无法把它和一个表示层面的效应区分开；约 6B 可以。这是最该做的下一个实验。

## 8. 工程陷阱（都实际付出过代价）

- **`/tmp` 会被周期性清空。** base dir 曾在 `/tmp/nsmb_out`，里面是数据与 tokenizer
  的符号链接和全部 checkpoint。它在运行中途消失，直接搞崩两个臂并**销毁了当时研究
  里的每一个 checkpoint**。结果得以保留只因为日志写在仓库内的 `runs/logs/`。
  §4.1 的诊断没有重跑就不可复现。现在 base dir 在 `/mnt/3fs/.../nsmb_out`。
- **绝不要用 `pgrep -f <名字>` 判活。** 检查用的那个 shell 自己的命令行里就含有这个
  模式，所以永远匹配得上。这造成了**五次**误判、把 4 张 GPU 空转数小时。**加方括号
  的写法（`base_tra[i]n`）也会失效** —— 探测命令经 `zsh -c 'eval ...'` 执行时，
  字面串出现在它自己的 argv 里。**唯一可信的判活信号是 GPU 显存**
  （`nvidia-smi --query-gpu=memory.used`）。
- **`kill -0 <pid>` 对僵尸进程会成功。** 一个已结束未回收的 driver 让等待者永远循环。
  要检查进程状态，不只是 PID 是否存在。
- **`--device-batch-size` 不是免费旋钮。** 在行数、参数、token 预算全部固定下直接
  实测：**dbs=4 比 dbs=8 好 0.00184。** `bos_bestfit` 加载器按批做文档装箱，所以
  dbs 改变的是 token 流本身，不只是梯度累积的调度。我曾在三个脚本头里把它写成
  "数值上等价，只是更慢"，这是错的。第 11 轮在同一次容量扫描里混用了 dbs=8 和
  dbs=4，导致 5 个臂里有 2 个作废，而且事后无法把它和容量效应分开。**绝不要在一次
  比较内部改变它。**
- **每一个新 buffer 都要在 `init_weights` 路径上显式重置。** `to_empty()` 会把 buffer
  填成垃圾，`nn.Module.__init__` 里的默认值不会存活。这个 bug 上线过一次：PQ 码本从
  ~1e38 开始，commitment loss 读到 3.2e26。定义行为的 buffer（LSH 位阈值、Engram
  命中率）还应当是 persistent 的，否则恢复训练会在恢复的那一步静默改变模型行为。
- **跨轮串联要带存活检查。** 用"在前一个 driver 的日志里轮询标记串"来排序工作是对的
  （`kill -0` 对僵尸会成功，PID 会复用，日志行不会），但我给的只有 24 小时上限，
  没有"日志变陈旧就放弃"。第 15 轮的 driver 被外部 SIGTERM 杀掉后，第 16 轮就礼貌地
  等了那个永远不会打印的标记 **16 小时**，四张 GB200 全程空转。
- **外部 SIGTERM 会杀掉 driver。** 已发生两次（第 14 轮第 1 臂 step 166；第 15 轮
  第 4 臂 step 950），`setsid nohup` + `disown` 并不能完全避免。所有 `run_arm` 都带
  幂等保护（跳过日志里已有 `Total training time` 的臂），所以**重启永远是安全的**，
  会从第一个未完成的臂继续。
- Engram 的运行需要 `TORCHDYNAMO_CACHE_SIZE_LIMIT=64`（许多不同的参数形状会让融合的
  AdamW step 反复重编译）。
- 系统 `torchrun` 指向的 python 在 `libucc` 上 import torch 会失败；用 venv 里的
  `torchrun`。

## 9. 下一步建议

第 18 轮之后重排。组合方向里已经**没有便宜的等参臂**了：预算划分已走完（§3.6，
不对称、偏专家），剩下每一项都需要新机器（`--moe-seed`、无-Engram 对照）或更多算力
（长时程、CORE）。

1. **把 `combo_iso` 做硬，并去掉混淆。** 它是本研究最大的等参收益（−0.00236，4.66 倍，
   完全分离），但只有 n=3，而且**三个 seed 共享同一个路由器抽样**，所以误差棒是下界。
   需要的两件事其实是同一件工作：实现 **`--moe-seed`**，然后让两个 seed 同时变化重跑
   `combo_iso`。这同时也修好了排行榜顶部 —— 至今没有任何 MoE 臂有可判定的误差棒。
2. **一个不带 Engram 的路由器对照，并保留统计。** §3.4 想问的机制交互问题因为 §1 的
   `mobius` 日志已被 `/tmp` 清理销毁（§8）而无法回答。`max_vio` 升到约 9 可能是这个
   配置的常态，也可能是 Engram 引起的；跑一次 3814 步的 `mobius`（带
   `--moe-log-every=200`）就能定，而这是读懂组合臂路由行为的前置条件。
3. **在那一对臂上做长时程实验（约 6B token）。** 池化是唯一剩下的大机制，而"每参数
   被训练得更好"这个领先假设有一个明确的、只能靠时程区分的预测（§7）。
4. **补 CORE 下游评测。** 67 个 checkpoint 尚存，可只做推理事后补测。整个研究都在
   优化 bpb，而效应量在 0.001（相对 0.13%）量级，**是否能在下游体现完全未知**。
   我预期 CORE 分辨不出 0.005 bpb 以下的差异 —— 那本身也是值得写进 §2 的结论。
   现在多了一个值得测的点：`combo_full` 相对 dense 是 0.01578，已经进入 CORE 有可能
   分辨的量级。
5. **外部值：kNN-LM / RETRO-lite。** §6 的原则指向的方向，也是唯一尚未尝试且有已发表
   证据支撑的方向 —— 而 §3.4 加强了这个指向：组合之所以有收益，正是因为收益来自残差流
   本身没有的信息。所有**内部**的重排 —— 13 种寻址、2 种行内容、4 种门控变体、
   3 次容量扫描、1 次头数扫描 —— 都回到了中性或更差。
6. **在线写入。** 真正"关系型"的版本：在当前文档上写入的记忆，携带 1500 token 之前
   的信息，而 2–3 token 的窗口和 SSSL 注意力模式都覆盖不到。

**不要再做：** 隐状态寻址的新量化器或新码宽（13 个臂）；更丰富的行内容（4 次测量，
固定行数下皆中性）；固定指数的读出白化（5.5 倍有害）；这种形式的更长 n-gram order
（1.8 倍更差）；计数通道上的 Fourier 基（两次单调，跨 seed 曲线相关 0.9996，而且这个
基会**掩盖**它所竞争的线性系数）；**更好的哈希函数**（表已饱和，均匀哈希对最大负载
已接近最优）；**更多哈希头**（4 倍扫描 0.13 倍，§5.2）；**在路由池旁边再加一个私有常开专家**
（0.65 倍，而且把 seed 误差棒抬到 1.04e-3 —— §3.5 判死 `--moe-shared-d-ff`）。最后两条合起来封闭了冲突这
条线：冲突有代价，但在这个规模上没有任何手段能减少它，唯一的把手是用门去折扣它。
